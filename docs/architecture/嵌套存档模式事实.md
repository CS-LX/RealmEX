# 嵌套存档模式事实（持久化对照）

> **文档性质**：社区「子世界 / 多维世界」实现的**抽象摘录**；RealmEX **借鉴目录约定**，**不采用**其运行时换档模型。  
> **不含**：实施方案。  
> **示例仓库**：[gitee.com/yangsanfengsc/sc-saghoulmod](https://gitee.com/yangsanfengsc/sc-saghoulmod)

---

## 1. 与 RealmEX 的关系

| 维度 | 嵌套存档换档模式 | RealmEX |
| --- | --- | --- |
| 磁盘布局 | 主档下子目录各有一套 `Project.xml` + chunk | **相同**（`Realms/<id>/`） |
| 运行时 | 同一时刻仅一个 `Project`；切换 ≈ Save + `GameLoading` | **多个** `SandboxProject` 并行 |
| 并行 tick | 否 | **是** |
| XML 合并 | 跨维合并 `Players` 等 | **不**合并沙箱 ECS 到主档 |

---

## 2. 嵌套存档模式定义

**不是**：

- 内存内第二 `Project` 与主世界并行（RealmEX 走此路）
- 同存档坐标划区
- UI 假地形

**是**：

- 每维度独立存档目录
- 切换 ≈ 保存 → 可选 XML 合并 → `GameLoading` 加载目标目录

---

## 3. 目录约定（抽象）

```text
<Worlds 根>/
  <主存档>/
    Project.xml
    Chunks*.dat
    <子维度名>/
      Project.xml
      Chunks*.dat
```

RealmEX 采用等价一层：`Realms/<realm_id>/`，由 `RealmHost` 管理，**不经** `ChangeWorld`。

---

## 4. `ChangeWorld` 常见步骤（社区实现，RealmEX 不执行）

1. 若目标目录不存在则创建最小 `Project.xml`
2. `GameManager.SaveProject`
3. 读取当前与目标 `Project.xml`，选择性合并节点（`Players`、`PlayerStats` 等）
4. `ScreensManager.SwitchScreen("GameLoading", ...)`

RealmEX 持久化 realm 时：**直接读写 `Realms/<id>/`**，主世界保持加载状态。

---

## 5. 与其它模式对照

| 维度 | 嵌套换档 | 坐标划区 | 假地形 | 并行 SandboxProject |
| --- | --- | --- | --- | --- |
| 真 Component 链 | 是 | 是 | 通常否 | 是 |
| 多域同时 tick | 否 | 是 | 视实现 | **是** |
| 分目录持久化 | 天然 | 难 | 常无 | **可选** |
| 切换 / 加载成本 | 高 | 低 | 低 | 中（双份初始化） |

---

## 6. 已知代价（换档模式，供对照）

- 每次切换有 I/O 与加载屏，不适合高频画中画沙箱
- 跨维数据依赖手写 XML 合并
- 不适合空间站「后台运转」类需求——这正是 RealmEX 存在的原因
