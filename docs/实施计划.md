## 2. 预设产品形态

### 2.1 Ponder 预设

目标是提供类似「机械动力」思索模块的教程与展示能力：用生动的镜头、步骤、文字、指示线、局部动画和真实设备状态，解释机器如何工作。

Ponder 预设的边界：

- 面向「教程 / 演示 / 说明」，默认短生命周期、内存态、可重播。
- 使用真实 `SandboxProject`，让方块、`BlockEntity`、Component 与 Subsystem 按游戏语义运行，不再用 UI 假地形模拟设备。
- 内容模组通过配置文件声明场景、镜头、步骤、方块布局、说明文本与可选交互点。
- 内容模组不需要自己再构建一套 SandboxProject / RealmHost / RealmViewport / Storyboard 体系。
- RealmEX 核心仍不写入工业、化学、电网等专有逻辑；内容模组专有 Subsystem 通过扩展入口注入。

Ponder 预设需要的能力：

- `RealmScene` 数据化加载：方块布局、初始实体、时间倍率、天气/光照等展示参数。
- `RealmStoryboard` 扩展步骤：等待、镜头移动、场景切换、方块高亮、文本气泡、箭头/区域标注、触发器。
- 轻量 `async/await` 语法层：对外提供 `await ctx.WaitFrames(...)`、`await ctx.WaitGameTime(...)`、`await ctx.ApplyScene(...)` 等写法，内部仍由 `SandboxRealm.Tick` 驱动，不引 UniTask。
- `RealmViewport` 真实离屏渲染：把沙箱内容绘制到 Widget / Dialog 中。
- 展示 UI：统一 Ponder Dialog / Widget，可由内容模组传入配置打开。
- 配置协议：先支持 RealmEX 自带示例格式，再允许内容模组按资产路径注册自己的教程包。

### 2.2 Create 预设

目标是提供一个可交互的小世界：玩家在大世界中打开或进入某个 Realm，并能与小世界交互、放置/破坏方块、观察机器运行。

Create 预设的边界：

- 面向「可编辑 / 可交互 / 可持久化」的小型沙盒空间，而不是只读教程。
- 玩家仍停留在主世界上下文中；`GameManager.Project` 不切到小世界。
- 小世界通过 `SandboxProject` 并行 tick，可按 Profile 决定是否保存到 `Realms/<id>/`。
- 交互入口由内容模组提供，例如方块、道具、机器面板或全屏 Hub。
- 放置、破坏、拾取、库存同步等副作用必须显式设计，默认不能泄漏到主世界。

Create 预设需要的能力：

- 可选持久化：`Persistence=On` 时保存并恢复 `Realms/<id>/`（属 **P4，已延后**）。
- 交互桥：把 UI / 方块入口里的玩家操作转换成沙箱内的放置、破坏、选择、拾取等命令。
- 权限与边界：限制可编辑范围、可用方块、是否允许实体生成、是否允许内容模组副作用。
- 视口输入：鼠标射线、方块选取、拖拽旋转/平移、快捷栏或工具模式映射。
- 主世界索引：长期小世界列表由内容模组自己的主世界 Subsystem 记录，RealmEX 只提供读写与运行能力。

### 2.3 模块边界

RealmEX 要保持「核心框架 + 可插拔上层模块」的结构。Ponder 预设与 Create 预设不能和核心类混在同一层，也不能反向渗透到核心生命周期里。

目标目录 / 命名空间按职责拆分：

- `RealmEX.Core`：`SandboxProject`、`SandboxRealm`、`RealmHost`、`RealmBootstrap`、`RealmProfile` 等基础运行时。
- `RealmEX.Core.Scenes`：`RealmScene` 与场景数据加载。
- `RealmEX.Core.Storyboard`：通用步骤、等待、场景切换、可复用协程语义。
- `RealmEX.Core.Rendering`：`RealmViewport`、Camera、RenderTarget 与沙箱绘制桥。
- `RealmEX.Core.Extensibility`：Contributor、模板扩展、内容模组注册入口。
- `RealmEX.Presets.Ponder`：Ponder Dialog / Widget、教程配置协议、镜头与标注步骤。
- `RealmEX.Presets.Create`：可交互小世界、输入桥、编辑权限与持久化体验。
- `RealmEX.Diagnostics`：F6 / F7 / F8 / F9 / F10 等游戏内诊断入口。

依赖方向只能从上层预设指向核心：`Presets.* -> Core`。核心不能引用 `Presets.Ponder` 或 `Presets.Create`，也不能写入某个内容模组的专有语义。后续新增更多预设时，按同样方式新增 `RealmEX.Presets.<Name>`，不改核心边界。

### 2.4 Core soft freeze（硬性要求）

自 P3d 诊断通过、转入可见 Ponder 起，`RealmEX.Core` 进入 **soft freeze**。下列条款为**硬性要求**，Agent / 开发不得因「方便做 UI」而绕过。

**禁止：**

- 为可见 Ponder Dialog / 世界动画重构 Host、`SandboxProject`、`SandboxRealm` 生命周期、Storyboard 驱动语义或 Viewport 核心绘制管线。
- 把 Dialog、caption、标注、教程配置、镜头脚本、示例内容写进 `Core`。
- 让 `Core` 引用 `Presets.Ponder` / `Presets.Create`，或把 Ponder 做成 Core 必需依赖。
- 借可见 Ponder 名义顺带做 P4 持久化、P5 Create 交互桥、大范围目录再拆分。

**允许（且仅限）：**

- 为 UI 上屏所必需的 **少量 additive** Core API：例如 Viewport 纹理暴露、resize / dispose 补齐、Camera 位姿 / FOV 等公开能力。
- 不改变现有不变量与诊断语义的小修（编译修复、空引用护栏、日志澄清）。

**落点：**

- Dialog / Widget / 打开关闭、步骤 caption、进度条、可见动画脚本、标注与示例 → **必须**落在 `Presets.Ponder`（诊断钩子可落在 `Diagnostics` / Loader）。
- 若发现「不做 Core 大改就无法上屏」，应先写清缺口与最小 additive API，再改 Core；不得借机重写 Core。

## 4. 近期建议顺序

1. **P3f：南瓜真实方块 Ponder（当前优先）**
   Create 式分步展示：田地 → 瓜苗 → 生长 → 成熟 → 南瓜灯。方块写入 `RealmEXPonderProject` 沙箱 Terrain，由 `RealmPonderBlockPresenter` 绘制。**遵守 §2.4：不大改 Core。**

2. **P3f 后续：配置协议与标注**
   把内置教程迁移 / 扩展为文件配置；补箭头、高亮、文本气泡等展示步骤。仍落在 `Presets.Ponder`。

3. **P5a：内容模组扩展入口**
   实现 Contributor 注入，供下游内容模组挂自有 Subsystem。

4. **P4：可选持久化（延后）**
   在可见 Ponder 与扩展入口之后再做；实现 `Persistence=On` 的 `Realms/<id>/` 保存恢复与 F11 M4 诊断。

5. **P5b：Create 预设**
   可交互小世界的输入、编辑与持久化体验。

## 5. 非目标

- 不把沙箱 `Project` 设为 `GameManager.Project`。
- 不用主世界远区块伪装小世界。
- 不在 RealmEX 核心写入工业、化学、电网等内容模组专有代码。
- 不要求内容模组复制 RealmEX 的 Host / Project / Viewport / Storyboard 基础设施。
- 不允许 Ponder / Create 预设反向成为核心运行时的必需依赖。
- **可见 Ponder 阶段不重写 Core，不提前做 P4 持久化。**
